# i18n(국제화) 설계

> 상태: **설계 완료 / 구현 미착수** — 라우트 구조 변경 범위가 커서 별도 PR 로 진행한다.
> README 로드맵의 `국제화(i18n) 지원` 항목에 대응한다.

---

## 1. 현재 상태

- 모든 UI 문구가 **한국어 하드코딩**. 문자열 리소스 분리 없음.
- `app/layout.tsx` 의 `<html lang='ko'>` 로 한국어 고정.
- 라우트 구조: `app/(main)/{category}/{tool}/page.tsx` (46+1개 도구, 정적 세그먼트).
- 도구 정의는 `app/data/*-tools.ts` 에 한국어 `name` / `description` 이 직접 들어 있음.

## 2. 목표

1. 한국어 / 영어 2개 언어 지원 (기본 한국어, `Accept-Language` 기반 자동 감지).
2. 도구 이름·설명·UI 라벨을 리소스 파일로 분리.
3. SEO 유지: 언어별 `<html lang>`, `hreflang` alternate, 언어별 sitemap.

## 3. 방식 비교

| 방식 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| **next-intl** (권장) | App Router 1급 지원, RSC 친화적, 메시지 포맷·복수형 지원, `hreflang` 자동 | `[locale]` 세그먼트 도입으로 전 라우트 이동 | ✅ 권장 |
| react-i18next | 생태계 큼 | App Router RSC 통합이 번거로움(클라이언트 위주) | ✗ |
| 자체 구현 (Context + JSON) | 의존성 0 | 복수형·포맷·SEO·라우팅을 직접 구현해야 함 | ✗ |

## 4. 권장 구조 (next-intl)

```
app/
├── [locale]/                     # ko | en
│   ├── (main)/
│   │   ├── page.tsx
│   │   ├── text/case-converter/page.tsx
│   │   └── ...
│   └── layout.tsx                # NextIntlClientProvider + <html lang={locale}>
├── api/                          # i18n 대상 아님 (경로 유지)
├── sitemap.ts                    # 언어별 엔트리 생성
└── middleware.ts                 # 로케일 감지/리다이렉트
messages/
├── ko.json
└── en.json
```

- URL 은 `/ko/text/case-converter`, `/en/text/case-converter` 형태가 된다.
- 기본 로케일(ko)은 `/` → `/ko` 리다이렉트 또는 `as-needed` 프리픽스 전략 중 선택 필요.

## 5. 마이그레이션 단계

1. **인프라**: `next-intl` 설치, `middleware.ts` + `[locale]/layout.tsx` 추가, `messages/{ko,en}.json` 생성
2. **라우트 이동**: `app/(main)` → `app/[locale]/(main)` 로 이동 (파일 이동만, 내용 변경 없음)
3. **도구 데이터 분리**: `app/data/*-tools.ts` 의 `name`/`description` 을 키로 바꾸고 `messages` 에서 조회
   - 예: `name: '텍스트 케이스 변환기'` → `nameKey: 'tools.case-converter.name'`
   - `app/data` 는 언어 중립(키)만 갖고, 실제 문구는 `messages/*.json` 으로 이동
4. **UI 문구 치환**: `useTranslations()` 로 라벨 교체 (컴포넌트 단위로 점진 적용)
5. **SEO**: `generateMetadata` 에서 `alternates.languages` 설정, sitemap 에 `hreflang` 추가
6. **테스트**: 언어 전환 시 라우팅/메타데이터 검증 테스트 추가

## 6. 영향 범위 / 리스크

- **영향 파일**: `app/**` 전체(약 60개), `app/data/*.ts` 5개, `sitemap.ts`, `robots.ts`
- **리스크**
  - 기존 URL 이 `/text/case-converter` → `/ko/text/case-converter` 로 바뀌므로 **외부 링크/북마크가 깨짐** → 리다이렉트 필요
  - `next/dynamic` + `ssr:false` 패턴과 `[locale]` 세그먼트 결합 시 검증 필요
  - 도구 데이터의 아이콘(React 컴포넌트)과 문구를 분리하는 리팩터링이 선행되어야 함
- **완화책**: 2단계(라우트 이동)와 3~4단계(문구 분리)를 별도 PR 로 분리해 리뷰 가능한 크기로 유지

## 7. 결정 필요 사항

1. 기본 로케일 URL 정책: `/` (프리픽스 없음) vs `/ko` 강제
2. 영어 번역을 누가/언제 제공할지 (초기에는 기계 번역 초안 + 검수?)
3. 기존 URL 유지가 필요한지 (리다이렉트 매트릭스 작성 여부)
