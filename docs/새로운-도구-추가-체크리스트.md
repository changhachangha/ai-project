# 새로운 도구 추가 체크리스트

## 📋 필수 체크리스트

### 1. 데이터 정의 단계

-   [ ] 해당 카테고리의 데이터 파일에 도구 정보 추가 (`app/data/`) — `section` 필드에 파일의 섹션을 기입
-   [ ] 새로운 섹션인 경우 `app/data/types.ts`의 `TOOL_SECTIONS`에 추가하고 `app/(main)/{section}/` 디렉터리 생성
-   [ ] 아이콘과 색상 정의
-   [ ] 설명 작성

### 2. 페이지 구현 단계

-   [ ] 해당 섹션 폴더에 도구 디렉토리 생성 (`app/(main)/{section}/{tool-id}/`)
-   [ ] `{ToolName}Client.tsx` 생성 (실제 기능 구현)
-   [ ] `components/tools/tool-host.tsx` 레지스트리에 `id → dynamic import` 엔트리 추가
-   [ ] 필요한 UI 컴포넌트 확인 및 생성

> 페이지/레이아웃/메타데이터/관련 도구는 `app/(main)/[section]/[tool]/` 동적 라우트가
> 데이터 레코드에서 자동으로 만든다. 도구별로 만드는 파일은 클라이언트 컴포넌트뿐이다.

### 3. 라우팅 검증 단계

-   [ ] `npm run dev` 실행
-   [ ] 홈페이지에서 새 도구가 표시되는지 확인
-   [ ] 사이드바에서 새 도구 클릭 시 올바른 경로로 이동하는지 확인
-   [ ] 직접 URL 입력으로 접근 가능한지 확인
-   [ ] 404 오류가 발생하지 않는지 확인

### 4. 기능 검증 단계

-   [ ] 도구의 기본 기능이 정상 작동하는지 확인
-   [ ] 오류 처리가 제대로 되는지 확인
-   [ ] 복사 기능이 작동하는지 확인
-   [ ] 모바일에서도 정상 작동하는지 확인

### 5. 통합 검증 단계

-   [ ] 다른 도구들이 여전히 정상 작동하는지 확인
-   [ ] 검색 기능에서 새 도구가 검색되는지 확인
-   [ ] 카테고리 필터링이 정상 작동하는지 확인
-   [ ] 즐겨찾기 기능이 작동하는지 확인

## 🚨 자주 하는 실수들

### 실수 1: `section` 필드 누락

**문제**: 도구 데이터를 추가했지만 `section`을 기입하지 않음
**해결**: `section`은 필수 필드 — `npm run type-check`가 누락을 바로 지적한다

### 실수 2: 경로 불일치

**문제**: 데이터의 `section`과 실제 폴더 구조가 다름
**해결**: `app/(main)/{section}/{id}` 디렉터리가 `section` 값과 일치하는지 확인 — `tools-smoke` 테스트가 검증한다

### 실수 3: 레지스트리 누락

**문제**: 데이터 파일에 도구를 추가했지만 `tool-host.tsx` 레지스트리에 등록하지 않음
**해결**: `tools-smoke` 테스트가 `getToolComponent(id)` 누락을 잡는다 — 레지스트리 엔트리 추가

### 실수 4: 컴포넌트 import 오류

**문제**: 새로운 UI 컴포넌트를 사용했지만 import하지 않음
**해결**: 필요한 컴포넌트가 `components/ui/`에 있는지 확인

### 실수 5: SSR 관련 오류

**문제**: 브라우저 전용 API를 서버에서 실행하려고 함
**해결**: `tool-host.tsx` 레지스트리 엔트리의 `dynamic()`에 `ssr: false` 지정
